# pm-brief：跟 PM（Ray）回報

Ray 多半在手機上看。用繁體中文，先給答案，短句。這週 Ray 問了 25 次以上「進度如何」，3 次「先給我連結」，4 次「引導我」，所以照下面三種寫法。

## A. 進度回報

**寫之前先對現況**：到 GitHub（`gh pr view`、`gh issue view`）和 ASC 查一次，不要照記憶或舊的回報寫。已經合併、已經上架、已經關掉的不要再列（iOS 1.0.0 上架後被當成待辦、10-29 已完成的事 10-31 又被列成待決）。

固定四段，沒有內容的段就省略：

```
**可以合併**（照這個順序）
1. <repo>#<n> <一句話>：<完整 URL>（draft 的寫「要先轉 Ready」）

**要你決定**
1. <問題>：建議 <選項>，因為 <一句理由>。你沒回的話我會 <預設做法>。<issue URL>

**要你動手**
1. <動作>，在 <哪台機器>：<見 B 段的寫法或連結>

**進行中**
- <誰> 在做 <什麼>，卡在 <什麼>／預計 <何時>
```

- 每一項都附完整 URL，不要只寫 #123。
- 「要你決定」一定附建議和預設做法，不要只丟選項。要 Ray 決定的事同時寫在 issue 並貼 `needs-ray`（`gh-handoff` skill）。
- **要 Ray 核准的，寫清楚怎麼回**：例如「同意的話回『#123 ok』」。Ray 在聊天按的綠勾或其他表情，bot 看不到，等於沒回（Wendy 因此漏排 15 篇）。Ray 一次核准好幾項時，請他列出編號。
- 預估時間沒把握就不要寫，寫了就要在超過時主動更新。
- Ray 問「進度如何」時，回答他問的那個專案；他沒指定就給全部，最重要的在前面。

## B. 請 Ray 動手

能自己做的不要丟給 Ray（例如模擬器截圖可以自己拍）。只有要密碼、要 Ray 的帳號、要實體操作、或被權限擋下的，才請 Ray 做。

一次一個步驟，每步這樣寫：

```
**第 N 步，在 <Mac mini／MBA／PC> 的 <Ghostty／終端機／系統設定／ASC 網頁>**
<要做什麼，一句話>

    <單行指令，可以直接複製貼上>

預期看到：<輸出的最後一行或畫面上的字>
做完回我：<要貼回來的東西，例如最後三行輸出>
```

- **指令要單行**、能直接貼上執行。多行的就先寫成腳本檔，請 Ray 執行那個檔。
- 腳本交出前：變數一律寫成 `${VAR}`（變數後面接全形括號「（」會被當成變數名的一部分，出過兩次 unbound variable），並跑過 `bash -n <檔>`。腳本要能重跑、改檔前先備份、會卡住的步驟加逾時。
- 寫明在哪台機器。透過 SSH 執行時，`~` 會在本機先展開，路徑要寫完整；SSH 連線讀不到鎖住的鑰匙圈，要密碼的指令沒有終端機可以輸入。
- **密碼和金鑰不印出來**：要產生的就直接放進剪貼簿，例如 `openssl rand -base64 32 | tr -d '\n' | pbcopy`，用完 `pbcopy < /dev/null` 清掉。不要請 Ray 把密碼貼在聊天裡，自己也不要在輸出裡印出含密碼的連線字串（`pgrep -fl` 會印出完整指令列）。
- 寫出預期結果，讓 Ray 知道做對了沒有。Ray 回貼後，對照預期再進下一步。

## C. 被權限擋下時

auto mode 或權限規則擋下合併、留言、刪檔這類動作時：

1. 不要換一個方法繞過去，也不要把被擋的指令和別的指令串在一起再試。
2. 要用到的內容（留言內文、腳本）先寫成檔，確認檔案真的存在（`ls -l <檔>`），再告訴 Ray。曾經說「檔案在那裡」其實沒寫出來。
3. 把被擋的那一條指令單獨交給 Ray，照 B 段的格式：在哪台機器、單行指令、預期結果。例如：

       gh pr comment 537 -R redtear1115/mars-dawn --body-file /tmp/pr537-result.md

4. Ray 跑完，自己去驗結果（例如 `gh pr view` 看留言在不在、PR 有沒有合併），再回報。
5. 同一類動作常被擋，建議 Ray 加進 allowlist，但由 Ray 決定，不要自己改設定。

## 不做

- 不用英文回報（compact 後和 subagent 的回報也一樣用中文）。
- 不在回報裡夾帶沒查證的狀態；不確定就寫「還沒確認」。
- 不替 Ray 輸入密碼、登入、按送審或發布。
